## Failures found and corrected

1. The AVR sketch accessed Timer1 registers and used Mega pin numbering. The ESP32 version replaces those with LEDC PWM and explicit ESP32 GPIO/UART assignments; the wiring test was observed failing before the migration.
2. Arduino sketch preprocessing placed autogenerated function declarations above the custom gate/pending types once ESP32 helpers were introduced. Explicit forward declarations corrected the real ESP32 compile failure.
3. The first ESP32 run busy-spun between polls. Under concurrent 3D rendering, simulation time lagged and the integration test reached COMPLETE while its wall-clock timeout expired during final local relocking. A short RTOS yield was added; the published final firmware passed the full test without relaxing that timeout or clearance interval.
4. Application links initially still pointed to the old Mega wireless project. A failing regression now selects the current ESP32 circuit only when observed telemetry identifies that controller.

Failed/initial serial logs and screenshots are retained as development history. The current passing live result is `mode: full`; a fault-only run or an old initial boot capture is not a substitute for it.

## Boundaries

Only the master runs as an emulated ESP32 CPU. The gateways and bay receiver/controllers remain labelled behavioural models over an ideal packet medium, not native ESP-NOW. Real RF, security, field wiring, motor supply/current, battery life and vehicle safety remain unverified. The scaled building uses its independent virtual-controller backend; this migration applies to the nine-bay circuit and its connected app/3D journey.
